### 2. 项目编写逻辑部分 (新增/深度)

这是**最重要的新增内容**，详细解释系统的架构思想和设计原则。

#### 2.1 整体架构思想 - 分层设计

```
表现层 (UI)
    ↕
API层 (FastAPI路由)
    ↕
业务层 (Service)
    ↕
数据层 (ORM)
    ↕
基础设施层 (DB/Redis/Queue)
```

每一层的责任清晰，易于理解和维护。

#### 2.2 核心设计原则 (4个)

**1. 关注点分离 (Separation of Concerns)**
- 前端 → 展示和交互
- API层 → 请求验证和路由
- 业务层 → 复杂业务逻辑
- 数据层 → CRUD操作

好处：便于测试、复用、维护

**2. 异步优先 (Async First)**
- 所有长时间操作都用Celery后台处理
- 用户无需等待
- 前端通过轮询/WebSocket监听进度

好处：用户体验好、系统稳定、可扩展

**3. 数据驱动 (Data Driven)**
- 清晰的数据流：上传 → 处理 → 存储 → 展示
- 每一步都有明确的数据模型

好处：逻辑清晰、易于调试、容易追踪

**4. 错误恢复 (Error Recovery)**
- Celery任务支持重试
- 异常详细记录
- 用户友好的错误提示

好处：系统健壮、风险可控

#### 2.3 代码组织逻辑

**后端组织**
- app/ → API路由层
- models/ → ORM模型层
- schemas/ → 请求/响应验证
